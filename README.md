# 古诗格律校勘台

面向诗词编辑与校勘人员的浏览器工作台。可逐字标注平仄、韵组和停顿，建立对仗关系，记录每条判断依据，并对多个异文版本进行并排定位。

## 功能

- 录入诗句并按五言、七言格律模板逐字对照。
- 平仄、停顿、韵组、判断依据和批注可逐字维护。
- 自动提示出律位置、一三五位置可接受变体、待标字和重复用韵。
- 建立句间对仗关系，记录关系说明。
- 多版本独立校勘，字符级并排比较与上下处差异定位。
- 文档级撤销/重做、键盘巡校和浏览器本地持久化。
- 离线校勘包协作：工作区保存「修改基线 + 整理者署名」，导出/导入 `.json` 校勘包。
  - 导出包带作品标识、整理者、基线快照与逐字位改动清单；
  - 导入按「句:字位」三方对账（基线／来稿／本机稿）：单方改动自动合并，双方不同用字进入「待确认冲突」，异文与批注均按来源保留、不覆盖已有内容；
  - 同一包重复导入只保留一条登记；
  - 导入前自动建立检查点，失败后工作区回滚并可一键从检查点重试；
  - 旧稿 schema 1 校勘包自动升级为当前格式后兼容导入。
- 导出包含字音标注、检查记录、合并基线、异文来源、来源批注与待确认冲突的 Markdown 校对稿。
- 针对平板和桌面优化布局，支持长时编辑。

## 本地开发

```bash
npm install
npm start
```

浏览器打开终端提供的本地地址。

### 离线协作流程

1. 在顶部填写**整理者署名**，在「版本与导出」为当前版本**保存修改基线**。
2. 断网逐字修改后，**导出 `.json` 校勘包**（包内含基线、署名与逐字位改动）。
3. 回到汇总工作区，在「离线合并」**导入校勘包**：
   - 相同改动自动合并；同一字位不同用字/标注进入「待确认冲突」；
   - 每个异文、每条批注都保留整理者与来源包，已有批注绝不被覆盖；
   - 同一包再次导入只计一条登记，不重复落字。
4. 冲突在「离线合并」中裁决：**采纳来稿 / 保留本机 / 并存为异文**，亦可「定位字格」回到逐字标注。
5. 导入若中途失败，顶部出现检查点条：工作区已回滚到导入前，可**从检查点重试**或放弃。
6. 旧稿（schema 1）校勘包导入时自动升级，异文按来源保留。

## 测试

```bash
npm test            # Karma + Chrome（需本机可用的 Chrome/Chromium）
npm run test:node   # 无 Chrome 环境下的离线逻辑测试（Node 直接执行）
```

`npm run test:node` 覆盖字位对账、三方合并、异文/批注来源保留、同包去重、
旧包升级与检查点重试等核心规则。

## 生产构建

```bash
npm run build
```

生产文件位于 `dist/app/browser/`。

## 键盘操作

| 快捷键 | 操作 |
| --- | --- |
| `↑ / ↓ / ← / →` | 在字格中移动 |
| `1 / 2 / 3` | 标为平 / 仄 / 中 |
| `R` | 循环切换韵组 |
| `Space` | 切换停顿标记 |
| `Ctrl/Cmd + Z` | 撤销 |
| `Ctrl/Cmd + Shift + Z` 或 `Ctrl/Cmd + Y` | 重做 |
| `Ctrl/Cmd + S` | 本地保存提示 |

## Docker

容器内由 nginx 监听端口 `80`，源码不硬编码宿主端口。

```bash
docker build -t classical-poetry-meter-editor .
docker run --rm -p 10015:80 classical-poetry-meter-editor
```

宿主端口 `10015` 仅用于本地运行示例，实际端口由根编排文件统一管理。
